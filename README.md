# Копилка — Telegram Mini App

Статический клиент Mini App для управления личным бюджетом. В браузере он работает как демо, а внутри Telegram получает тему и имя пользователя через Telegram Web Apps SDK.

## Подключение

1. Разместите папку на HTTPS-хостинге: Telegram не открывает `file://` и HTTP.
2. В [@BotFather](https://t.me/BotFather) создайте бота, затем в **Bot Settings → Menu Button → Configure menu button** укажите публичный HTTPS-адрес `index.html`.
3. Откройте чат с ботом и нажмите кнопку меню.

## Production

Пока данные хранятся локально в браузере Telegram и разделены по пользователям. Для синхронизации между устройствами нужен API и БД. На сервере проверяйте `Telegram.WebApp.initData` по HMAC с токеном бота; `initDataUnsafe` не является доверенной авторизацией.

## API и база данных (Cloudflare D1)

В проект добавлены `worker.js`, `schema.sql` и `wrangler.jsonc`. Worker проверяет подпись Telegram `initData`, а затем сохраняет финансовый профиль пользователя в D1. Токен бота не попадает в клиентский код или Git.

1. Установите Wrangler и выполните вход в Cloudflare:

   ```bash
   npm install -g wrangler
   wrangler login
   ```

2. Создайте базу и скопируйте её `database_id` из ответа:

   ```bash
   wrangler d1 create kopilka-db
   ```

3. Вставьте этот ID вместо `REPLACE_WITH_D1_DATABASE_ID` в `wrangler.jsonc`, затем примените схему:

   ```bash
   wrangler d1 execute kopilka-db --remote --file=schema.sql
   ```

4. Добавьте токен созданного в BotFather бота как секрет и опубликуйте Worker:

   ```bash
   wrangler secret put BOT_TOKEN
   wrangler deploy
   ```

После этого Mini App будет загружать и сохранять данные через `/api/state`. В браузерном режиме она продолжает работать локально; синхронизация включается только в Telegram.

## Цели в месячном бюджете

Карточка цели показывает остаток до цели, срок и рекомендованный месячный взнос. Расчёт использует календарные месяцы, включая текущий: с сентября по декабрь — четыре взноса. Если резерв уже включён, рекомендация учитывает пополнения текущего месяца, чтобы частичный взнос не уменьшал план повторно.

Пользователь включает резерв в форме цели и сохраняет предложенную или собственную сумму. Поля `monthlyEnabled`, `monthlyAmount`, `monthlyStartMonth` синхронизируются вместе с целью через существующий `/api/state`; миграция БД не требуется. У старых целей резерв по умолчанию выключен.

Резерв на месяц равен месячной сумме минус фактические пополнения (за вычетом снятий) этого месяца, ограничен оставшейся суммой цели и не может быть отрицательным. Первоначальные накопления новых целей отмечены `initialFunding` и не считаются регулярным взносом. Резерв уменьшает «Не распределено» и «Можно свободно потратить». Уже внесённые в цели деньги исключены из доступного остатка и второй раз не вычитаются.

На новый месяц резерв рассчитывается заново. Пропущенные взносы автоматически не накапливаются; рекомендация обновляется по оставшемуся сроку, а сохранённую месячную сумму пользователь меняет сам. Просроченная цель сохраняет резерв до достижения или отключения, с предупреждением о сроке. При достижении, отключении или удалении цели будущий резерв освобождается. Автоматических операций, списаний и новых уведомлений эта функция не создаёт.

Проверка расчётов: `node --test tests/goal-planning.test.cjs`.

## Главная — лента операций

Главная показывает весь список операций по убыванию даты и времени, с группировкой по дням. Отдельной вкладки истории больше нет. Верхняя карточка сохраняет свайп между текущим балансом и прогнозом свободных денег.

В ленте доступны поиск по комментарию или категории, периоды «За всё время», «Этот месяц», «Прошлый месяц» и фильтры типов. Итоги за день считаются по показанным доходам и расходам; стартовый баланс и переводы на цели доступны в «Все» и «Цели и баланс», но не увеличивают доходы или расходы дня. Верхний баланс всегда показывает общий доступный остаток и не зависит от фильтров ленты.

Нажатие на запись открывает редактирование; удаление находится в форме операции и требует подтверждения. Плавающая кнопка «+» на главной открывает выбор дохода или расхода. Напоминания доступны компактной ссылкой над лентой.

## Планирование от зарплаты до зарплаты

В финансовом плане можно выбрать календарный месяц или ровно 15 календарных дней от даты одной из зарплат. Периоды идут без пересечений: например, 5–19 сентября, 20 сентября–4 октября. При новом запуске открывается текущий цикл. Стрелки показывают соседние периоды; режим и дата сохраняются в синхронизируемом состоянии пользователя. Это не режим фиксированных чисел месяца (например, 5-го и 20-го).

Месячные бюджеты остаются в `state.plans['YYYY-MM']`, короткие — в `state.plans['15d:YYYY-MM-DD']`. Расходы короткого периода всегда пересчитываются по датам операций, включая изменения и удаления. Переключение не переносит и не стирает бюджеты другого режима. Не распределено = текущий доступный остаток − платежи периода − остатки бюджетов сверх этих платежей − резерв целей. Напоминание внутри бюджета той же категории не учитывается дважды. Для будущего/прошедшего периода явно указан расчёт от текущего остатка, без выдуманной будущей зарплаты или исторического баланса.

В коротком плане ежемесячный взнос цели распределяется пропорционально календарным дням периода; фактические пополнения уменьшают резерв. Резерв ограничен оставшейся суммой цели. Карточка свободных денег на главной использует текущий период выбранного режима, независимо от просмотра соседнего периода в плане.

## Интервалы напоминаний и полноэкранный запуск

Плановые платежи находятся на экране «Финансовый план», под бюджетами и целями: добавление, редактирование и действия с напоминанием доступны на месте. Ссылки на напоминания с главной и из Telegram открывают этот же экран. Список показывает все расписания; денежный резерв выше учитывает выбранный период. Цвет полоски бюджета показывает только текущий статус: красный при превышении лимита, фиолетовый в пределах лимита, независимо от цвета категории. Изменение лимита сразу обновляет цвет, процент и остаток.

Напоминания поддерживают день, неделю, **каждые 15 дней**, месяц и год. Интервалы рассчитываются в часовом поясе напоминания, с сохранением времени. Пропуск/подтверждение переводит расписание на следующий срок; никаких автоматических записей в финансовую историю не создаётся. Просроченный неразрешённый платёж резервируется один раз, а не за каждый пропущенный интервал.

Миграция `0003_payment_intervals.sql` добавляет поле `interval_days` без пересоздания таблиц, удаления платежей или напоминаний. Поле переопределяет старый `cadence`; API возвращает понятные значения `daily` и `every_15_days`. Перед публикацией нового Worker обязательно применить миграцию через `wrangler d1 migrations apply kopilka-db --remote`, затем `wrangler deploy --keep-vars`. Старый Worker совместим с добавлением пустого поля; новый нельзя публиковать до успешной миграции. После создания новых интервалов откат к Worker без их поддержки недопустим без отдельной миграции расписаний.

Telegram 8.0+ запрашивает fullscreen при запуске. При отказе/отсутствии поддержки остаётся раскрытый обычный режим. Верхние и нижние отступы учитывают безопасные области устройства и элементы Telegram.

Проверки: `node --test tests/*.test.cjs` (Node.js 24+, используется встроенный SQLite для проверки миграции и серверных запросов). Тесты покрывают 15-дневные границы, переходы месяцев/лет/DST, резервы, совместимость старых расписаний и fullscreen fallback. Нативный fullscreen требует дополнительной проверки на телефоне в Telegram.
